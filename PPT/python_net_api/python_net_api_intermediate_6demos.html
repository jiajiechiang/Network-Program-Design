中階 API 自動化環境準備：
中階篇我們將跳脫簡單的 Basic Auth 查詢，深入企業級 API 互動架構：

Demo 1 Bearer Token 身份驗證：存取現代控制器 (如 Cisco DNA Center / Catalyst Center)

現代網管控制器 (如 DNAC) 通常採用 Token 機制。我們必須先發送 POST 請求換取 Token，之後的每一個 API 請求都必須在 Headers 帶上 Authorization: Bearer <token>。

api_bearer_token.py
import requests
import urllib3
urllib3.disable_warnings(urllib3.exceptions.InsecureRequestWarning)

controller_url = "https://dnac.corporate.local"

# 1. 發送 POST 請求換取 Token
auth_url = f"{controller_url}/api/v1/auth/token"
response = requests.post(auth_url, auth=('api_user', 'password123'), verify=False)

if response.status_code == 200:
    token = response.json().get('Token')
    print("✅ 成功取得 Bearer Token！")
    
    # 2. 使用取得的 Token 訪問受保護的網路設備清單 API
    headers = {
        "Authorization": f"Bearer {token}",
        "Content-Type": "application/json"
    }
    
    devices_url = f"{controller_url}/api/v1/network-device"
    dev_response = requests.get(devices_url, headers=headers, verify=False)
    
    print("網路設備清單查詢結果：", dev_response.json())
else:
    print("❌ Token 取得失敗：", response.status_code)

Demo 2 RESTCONF PATCH 請求：精準修改網路設備特定參數

使用 POST 會覆蓋整個節點，而 PATCH 允許我們對設備設定進行「局部更新 (Partial Update)」。此範例示範透過 PATCH 修改特定介面的描述 (Description)。

api_restconf_patch.py
import requests
import urllib3
urllib3.disable_warnings(urllib3.exceptions.InsecureRequestWarning)

# 目標特定介面的 RESTCONF 網址
api_url = "https://192.168.1.1/restconf/data/ietf-interfaces:interfaces/interface=GigabitEthernet1"

headers = {
    "Accept": "application/yang-data+json",
    "Content-Type": "application/yang-data+json"
}

# 僅修改描述欄位，其餘設定保持不變
payload = {
    "ietf-interfaces:interface": [
        {
            "name": "GigabitEthernet1",
            "description": "Updated via RESTCONF PATCH by Python"
        }
    ]
}

response = requests.patch(
    api_url, 
    headers=headers, 
    json=payload, 
    auth=('admin', 'secret'), 
    verify=False
)

print("PATCH 回應狀態碼：", response.status_code)
if response.status_code in [200, 204]:
    print("✅ 成功局部更新介面描述！")
else:
    print("❌ 更新失敗：", response.text)

Demo 3 RESTCONF DELETE 請求：透過 API 自動刪除設定

當業務下線或 VLAN 需移除時，我們可以使用 DELETE 請求精準刪除設備上的特定設定節點。

api_restconf_delete.py
import requests
import urllib3
urllib3.disable_warnings(urllib3.exceptions.InsecureRequestWarning)

# 指定要刪除的特定 VLAN 100 網址
api_url = "https://192.168.1.1/restconf/data/Cisco-IOS-XE-native:native/vlan/vlan-list=100"

headers = {
    "Accept": "application/yang-data+json"
}

response = requests.delete(
    api_url, 
    headers=headers, 
    auth=('admin', 'secret'), 
    verify=False
)

print("DELETE 回應狀態碼：", response.status_code)
if response.status_code in [200, 204]:
    print("✅ 成功透過 API 刪除 VLAN 100！")
else:
    print("❌ 刪除失敗或該 VLAN 不存在：", response.text)

Demo 4 GraphQL 網路查詢：向現代網管系統發送精準查詢

傳統 REST API 常常會回傳一堆不需要的欄位。現代網管系統 (如 NetBox) 支援 GraphQL，讓您可以像點菜一樣，精準指定您想要的欄位與結構。

api_graphql_query.py
import requests
import json

graphql_url = "https://netbox.corporate.local/graphql/"
headers = {
    "Authorization": "Token 0123456789abcdef0123456789abcdef01234567",
    "Content-Type": "application/json"
}

# 定義 GraphQL 查詢語法：只要查詢設備名稱與其介面清單
query_payload = {
    "query": """
        {
          device_list {
            name
            site { name }
            interfaces {
              name
              enabled
            }
          }
        }
    """
}

response = requests.post(graphql_url, headers=headers, json=query_payload, verify=False)

if response.status_code == 200:
    result = response.json()
    print("=== GraphQL 精準查詢結果 ===")
    print(json.dumps(result, indent=4, ensure_ascii=False))
else:
    print("GraphQL 查詢失敗：", response.text)

Demo 5 非同步 API 請求 (Asyncio + Httpx)：十倍速並發巡檢多台設備

當需要同時向 50 台網路設備發送 REST API 查詢時，傳統同步 requests 會花費大量時間等待。透過 httpx 與 asyncio 實現非同步併發，秒級完成全網 API 巡檢。

api_async_requests.py
import asyncio
import httpx

async def fetch_device_status(client, ip):
    url = f"https://{ip}/restconf/data/ietf-system:system-state"
    try:
        # 非同步發送 GET 請求
        response = await client.get(url, auth=('admin', 'secret'), timeout=3)
        if response.status_code == 200:
            print(f"✅ [{ip}] 查詢成功！")
    except Exception as e:
        print(f"❌ [{ip}] 連線失敗: {e}")

async def main():
    devices = [f"192.168.1.{i}" for i in range(1, 11)] # 模擬 10 台設備
    
    # 建立非同步 HTTP Client (關閉 SSL 驗證)
    async with httpx.AsyncClient(verify=False) as client:
        tasks = [fetch_device_status(client, ip) for ip in devices]
        # 同時發出所有請求
        await asyncio.gather(*tasks)

if __name__ == "__main__":
    asyncio.run(main())

Demo 6 網管自動化架構：編寫 Flask 接收設備 Webhook 事件

現代網路設備支援事件驅動 (Event-driven) 自動化。當設備發生介面斷線或設定變更時，會主動發送 HTTP POST 到我們的伺服器。此範例教您用 Flask 接收並處理來自設備的 Webhook。

api_webhook_receiver.py
from flask import Flask, request, jsonify

app = Flask(__name__)

@app.route('/api/v1/webhook/network-event', methods=['POST'])
def receive_network_webhook():
    event_data = request.json
    
    if not event_data:
        return jsonify({"error": "Invalid JSON payload"}), 400
        
    # 解析設備主動推播的事件內容
    device_ip = event_data.get('device_ip')
    event_type = event_data.get('event_type')
    message = event_data.get('message')
    
    print(f"🚨 [收到設備 Webhook 事件] 來自: {device_ip} | 類型: {event_type} | 內容: {message}")
    
    # 這裡可以自動串接邏輯 (例如發送 Line/Teams 告警或觸發備份)
    
    return jsonify({"status": "success", "message": "Event received and processed."}), 200

if __name__ == '__main__':
    # 啟動 Webhook 接收伺服器
    app.run(host='0.0.0.0', port=5000)
