Demo 1 密碼安全加密：使用 Flask-Bcrypt

絕對不能把使用者密碼用明文存進資料庫！我們必須使用 Bcrypt 演算法進行雜湊 (Hashing) 與加鹽 (Salting)，確保即使資料庫外洩，密碼也不會被破解。

app_bcrypt.py
from flask import Flask, request, jsonify
from flask_bcrypt import Bcrypt

app = Flask(__name__)
bcrypt = Bcrypt(app)

# 模擬資料庫儲存雜湊後的密碼
fake_db = {}

@app.route('/register', methods=['POST'])
def register():
    username = request.json.get('username')
    password = request.json.get('password')
    
    # 1. 將密碼進行雜湊加密
    hashed_password = bcrypt.generate_password_hash(password).decode('utf-8')
    fake_db[username] = hashed_password
    
    return jsonify({"message": "註冊成功，密碼已安全加密！"})

@app.route('/login', methods=['POST'])
def login():
    username = request.json.get('username')
    password = request.json.get('password')
    
    stored_hash = fake_db.get(username)
    if stored_hash and bcrypt.check_password_hash(stored_hash, password):
        return jsonify({"message": "登入成功！密碼驗證通過。"})
        
    return jsonify({"error": "帳號或密碼錯誤"}), 401

Demo 2 無狀態 API 安全：JWT 驗證 (Flask-JWT-Extended)

在現代前後端分離或 App 開發中，伺服器不保存 Session，而是發放 JWT (JSON Web Token) 給客戶端。客戶端之後每次請求只要帶上這張「數位通行證」即可。

app_jwt.py
from flask import Flask, request, jsonify
from flask_jwt_extended import (
    FlaskJWTExtended, create_access_token, jwt_required, get_jwt_identity
)

app = Flask(__name__)
app.config['JWT_SECRET_KEY'] = 'super-secret-jwt-key' # 簽章密鑰
jwt = FlaskJWTExtended(app)

@app.route('/api/login', methods=['POST'])
def api_login():
    username = request.json.get('username')
    # 假設驗證成功...
    if username == 'admin':
        # 產生 JWT Token (可將使用者身分包在裡面)
        access_token = create_access_token(identity=username)
        return jsonify(access_token=access_token)
    return jsonify({"msg": "Bad username"}), 401

@app.route('/api/protected', methods=['GET'])
@jwt_required() # 加上這個裝飾器，代表必須帶有有效的 JWT 才能訪問
def protected():
    current_user = get_jwt_identity() # 取得當前 Token 內的使用者身分
    return jsonify(logged_in_as=current_user, message="成功訪問受保護的 API 資源！")

Demo 3 資料庫版本控制：Flask-Migrate (Alembic)

當專案上線後，如果資料庫需要「新增欄位」(例如使用者多出 `age` 欄位)，直接刪除重建資料庫會導致舊用戶資料遺失。使用 Flask-Migrate 可以像 Git 一樣管理資料庫結構的每次異動。

app_migrate.py 與終端機指令
# 1. 在 app.py 中初始化 Migrate
from flask import Flask
from flask_sqlalchemy import SQLAlchemy
from flask_migrate import Migrate

app = Flask(__name__)
app.config['SQLALCHEMY_DATABASE_URI'] = 'sqlite:///app.db'
db = SQLAlchemy(app)
migrate = Migrate(app, db) # 綁定 Migrate

class User(db.Model):
    id = db.Column(db.Integer, primary_key=True)
    name = db.Column(db.String(50))
    # 之後若新增欄位：age = db.Column(db.Integer)

# 2. 在終端機執行的指令 (Command Line)：
# flask db init    (初始化遷移資料夾，只需執行一次)
# flask db migrate -m "Add user table" (偵測模型改變，自動產生遷移檔)
# flask db upgrade (將變更真正套用到資料庫中)

Demo 4 效能加速：整合 Redis 快取機制

高流量網站不能每次都查詢資料庫。我們透過 Redis 記憶體資料庫，將運算結果或查詢結果暫存起來，大幅降低後端與資料庫的負擔。

Demo 5 非同步背景任務：Celery 任務佇列

當網站需要處理「寄送大量 EDM」、「產生 PDF 報表」等會讓 HTTP 請求逾時的任務時，必須交給 Celery 放到背景非同步執行。

tasks.py (Celery Worker)
from celery import Celery
import time

# 初始化 Celery，使用 Redis 作為訊息代理 (Broker)
celery_app = Celery(
    'tasks',
    broker='redis://localhost:6379/0',
    backend='redis://localhost:6379/0'
)

@celery_app.task
def generate_heavy_report(user_id):
    print(f"開始為使用者 {user_id} 產生大型報表...")
    time.sleep(10) # 模擬耗時 10 秒的運算
    print(f"報表產生完畢，已發送通知信給使用者 {user_id}")
    return "Report Ready"

# 在 Flask 主程式中呼叫方式：
# from tasks import generate_heavy_report
# generate_heavy_report.delay(user_id=42)  # .delay() 會立即返回，任務在背景執行

Demo 6 企業級日誌管理 (Structured Logging)

正式環境絕對不能只用 `print()`。我們必須使用 Python 內建的 logging 模組，將系統錯誤、警告與訪問紀錄自動寫入日誌檔案，方便後續除錯與監控。

app_logging.py
import logging
from logging.handlers import RotatingFileHandler
from flask import Flask

app = Flask(__name__)

# 設定日誌格式與寫入檔案 (設定檔案最大 1MB，最多保留 3 個備份檔)
handler = RotatingFileHandler('app.log', maxBytes=1024*1024, backupCount=3)
handler.setLevel(logging.INFO)
formatter = logging.Formatter('[%(asctime)s] %(levelname)s in %(module)s: %(message)s')
handler.setFormatter(formatter)

app.logger.addHandler(handler)
app.logger.setLevel(logging.INFO)

@app.route('/do-something')
def do_something():
    app.logger.info("使用者訪問了 /do-something 路由")
    try:
        # 模擬業務邏輯
        result = 10 / 2
        return f"計算結果：{result}"
    except Exception as e:
        app.logger.error(f"系統發生嚴重錯誤：{e}", exc_info=True)
        return "伺服器內部錯誤", 500
