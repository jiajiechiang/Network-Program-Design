Demo 1 企業必備：自訂使用者模型 (Custom User Model)

Django 官方強烈建議，在專案一開始就使用 AbstractUser 自訂使用者模型。未來如果想把登入方式從「帳號」改成「Email」，或增加「手機號碼」欄位，都會非常方便。

users/models.py
from django.contrib.auth.models import AbstractUser
from django.db import models

class CustomUser(AbstractUser):
    # 新增自訂欄位，例如：手機號碼與大頭貼
    phone_number = models.CharField(max_length=15, blank=True, null=True)
    avatar = models.ImageField(upload_to='avatars/', blank=True, null=True)

    def __str__(self):
        return self.username
myproject/settings.py
# 告訴 Django 不要使用內建的 User，改用我們剛剛寫的 CustomUser
AUTH_USER_MODEL = 'users.CustomUser'

Demo 2 DRF 進階：使用 ViewSets 與 Routers

在中階篇我們使用了 @api_view，但當你要做完整的 CRUD (增刪改查) 時，程式碼會很長。ViewSets 搭配 Routers 可以用不到 5 行程式碼，自動產生完整且符合 RESTful 規範的 API (含列表、詳細、新增、修改、刪除)。

myapp/views.py
from rest_framework import viewsets
from .models import Article
from .serializers import ArticleSerializer

# ModelViewSet 已經內建了 CRUD 的所有邏輯
class ArticleViewSet(viewsets.ModelViewSet):
    queryset = Article.objects.all()
    serializer_class = ArticleSerializer
myproject/urls.py
from django.urls import path, include
from rest_framework.routers import DefaultRouter
from myapp.views import ArticleViewSet

# 建立路由器並註冊 ViewSet
router = DefaultRouter()
router.register(r'articles', ArticleViewSet)

urlpatterns = [
    # Router 會自動幫我們產生 /articles/ 以及 /articles/<id>/ 的 API 節點
    path('api/', include(router.urls)),
]

Demo 3 API 安全：JWT 身份驗證 (SimpleJWT)

前後端分離架構中，Cookie/Session 容易遇到跨網域 (CORS) 問題。業界標準是使用 JSON Web Token (JWT)。前端登入後取得 Token，之後每次發 API 都在 Header 帶上 Token 證明身分。

myproject/settings.py
REST_FRAMEWORK = {
    'DEFAULT_AUTHENTICATION_CLASSES': (
        'rest_framework_simplejwt.authentication.JWTAuthentication',
    ),
}
myproject/urls.py
from rest_framework_simplejwt.views import (
    TokenObtainPairView,
    TokenRefreshView,
)

urlpatterns += [
    # 發送 POST 給此網址(帶入 username 與 password)，若正確則回傳 Access Token 與 Refresh Token
    path('api/token/', TokenObtainPairView.as_view(), name='token_obtain_pair'),
    # Access Token 過期時，用此網址換發新 Token
    path('api/token/refresh/', TokenRefreshView.as_view(), name='token_refresh'),
]

Demo 4 非同步背景任務：Celery + Redis

如果在使用者按下註冊後，伺服器要寄送驗證信 (耗時 3 秒)，使用者就會卡在白畫面。我們應該將這類耗時任務交給 Celery 放到背景執行 (Background Tasks)。

myapp/tasks.py
from celery import shared_task
import time

# 宣告這是一個 Celery 背景任務
@shared_task
def send_welcome_email(user_email):
    print(f"開始寄送信件給 {user_email}...")
    time.sleep(5) # 模擬耗時的寄信動作
    print("信件寄送完畢！")
    return "Success"
myapp/views.py
from django.http import JsonResponse
from .tasks import send_welcome_email

def register_user(request):
    # ... 處理註冊邏輯 ...
    
    # 使用 .delay() 呼叫任務，任務會被丟進 Redis 佇列，由背後的 Celery Worker 執行
    # Django 可以立刻回傳 Response，完全不需等待！
    send_welcome_email.delay('newuser@example.com')
    
    return JsonResponse({"message": "註冊成功！驗證信已在背景寄出。"})

Demo 5 提升百倍效能：Redis 快取機制 (Caching)

對於流量極大的頁面 (如首頁、排行榜)，每次造訪都去資料庫重新計算是非常耗能的。我們可以使用 Django 內建的快取機制，將結果暫存在記憶體 (Redis) 中。

myproject/settings.py
# 設定 Django 使用 Redis 作為快取後端
CACHES = {
    "default": {
        "BACKEND": "django_redis.cache.RedisCache",
        "LOCATION": "redis://127.0.0.1:6379/1",
        "OPTIONS": {
            "CLIENT_CLASS": "django_redis.client.DefaultClient",
        }
    }
}
myapp/views.py
from django.views.decorators.cache import cache_page
from django.shortcuts import render
from .models import Article

# 使用裝飾器，將這個頁面的結果快取 15 分鐘 (60秒 * 15)
# 接下來 15 分鐘內的所有造訪，Django 都不會查詢資料庫，直接從 Redis 秒回傳結果！
@cache_page(60 * 15)
def popular_articles(request):
    articles = Article.objects.order_by('-views')[:10] # 非常耗時的查詢
    return render(request, 'myapp/popular.html', {'articles': articles})

Demo 6 即時通訊：Django Channels (WebSockets)

傳統的 HTTP 只能「前端問，後端答」。如果要做聊天室或股票即時報價，必須使用 WebSockets 達成雙向通訊。Django Channels 賦予了 Django 處理 WebSocket 的能力。

myapp/consumers.py
import json
from channels.generic.websocket import AsyncWebsocketConsumer

# 類似於 View，但專門處理 WebSocket 連線
class ChatConsumer(AsyncWebsocketConsumer):
    async def connect(self):
        # 接受前端的 WebSocket 連線請求
        await self.accept()
        # 主動推播訊息給前端
        await self.send(text_data=json.dumps({
            'message': '連線成功！歡迎來到聊天室'
        }))

    async def disconnect(self, close_code):
        pass # 處理斷線邏輯

    async def receive(self, text_data):
        # 接收到前端傳來的訊息
        text_data_json = json.loads(text_data)
        message = text_data_json['message']

        # 把訊息原封不動回傳給前端 (Echo Server 概念)
        await self.send(text_data=json.dumps({
            'message': f"伺服器已收到您的訊息: {message}"
        }))
